# 机器人推理放在哪里：新版模型、TCO与网络墙

**报告日期：** 2026-09-14  
**原文：** https://newsletter.semianalysis.com/p/a-brain-too-big-to-carry-on-device

## 一句话结论

机器人不会在“全部端侧”与“全部云端”之间二选一。安全、伺服和高频动作必须留在本机，低频规划与复杂推理才有条件进入数据中心。新版报告把核心经济参数更新为B300单卡可在500ms动作块时限内服务12台机器人，并加入96台机器人TCO与多家公司实地案例；与此前概览相比，这是实质修订，应单独记录。

## 模型、时延与分层

当前通用机器人模型多为数十亿参数：π0约3B、π0.7约5B、GR-3约4B、部分Generalist模型约10B、DreamZero约14B。规模并不代表终局，而是受机器人数据、功耗、内存和实时期限共同限制。DreamZero需要两张GB200才能实时运行，后续RoboTTT却用约3B策略模型与测试时训练换取分钟级上下文，说明算法效率会持续改变硬件边界。

报告按频率划分三层：

- **伺服与安全层：** 数百Hz，100Hz意味着每10ms必须给出动作；无线往返通常10—50ms，不能外包。
- **动作/运动层：** 高频、强确定性，网络一旦失效就成为安全故障，原则上留在端侧。
- **规划/System 2：** 通常低于20Hz；5Hz决策有约200ms预算，理论上可把更大模型放在数据中心。难点不是平均延迟，而是尾部抖动。

[Jetson Thor官方规格](https://www.nvidia.com/en-gb/autonomous-machines/embedded-systems/jetson-thor/)为最高128GB LPDDR5X、40—130W，而报告估算其FLOPs约为GB200的十分之一、内存带宽约三十分之一。端侧平台更省电、更确定；数据中心平台则能共享高价算力并运行更大模型。

## 96台机器人的三种TCO

报告用带TTT模块的GR00T N1.7重构负载衡量服务成本，不代表RoboTTT真实任务准确率。测试中，一张B300在p99、500ms动作块期限内可服务12台机器人；RTX 6000 Pro为4台。

| 方案 | 假设 | 初始资本开支 | 全部TCO/小时 |
|---|---|---:|---:|
| B300数据中心 | 1台8-GPU服务器，96个无线板 | 约55.4万美元 | 18.63美元 |
| RTX 6000 Pro | 3台8-GPU服务器 | 约43.6万美元 | 15.61美元 |
| Jetson Thor端侧 | 96个模块及底板、存储、散热、电池和通信 | 约39.4万美元 | 14.97美元 |

静态总成本看端侧略低，但利用率改变结论。报告基准设B300池化利用率90%、工业机器人端侧芯片40%，折算每FP4 dense PFLOP小时成本约0.17美元与0.37美元，数据中心只有端侧的约46%；家庭机器人若每天只运行1—2小时，差距可能扩大到约12%。在标准工业场景中，当每张B300批量服务达到约5台机器人，外置推理开始胜过端侧。

这些数字不能被解释为“云端一定便宜”。它们高度依赖机器人并发、服务器利用率、无线改造成本、寿命、资本成本、云租价和任务deadline；本地只有少量机器人而服务器长期闲置时，端侧仍可能更好。

## 真实部署为什么仍偏端侧

报告案例展示了任务而非厂商口号决定架构：

- **Boston Dynamics：** 把高层System 2放在Google基础设施，通过云端模型给本地VLA标注目标、监督和纠错；安全与动作仍留在机器人。代价是专门团队处理无线、客户数据和合规。
- **Agility Robotics：** Digit把策略模型放在Jetson级端侧，云只做编排、工作流、地图、升级和遥操作；工厂金属环境、漫游和安全认证使端侧更稳妥。
- **Verne、Sunday、Weave：** 仓储或家庭环境即使平均延迟尚可，Wi-Fi死角、邻居拥塞、网状路由和尾延迟也会破坏长时间成功率，因此更倾向端侧。

网络墙不是简单增加带宽。要实现云端规划，需要机器人优先的上行调度、位置感知波束成形、全站统一时钟、多链路Wi-Fi/5G冗余、RF实测布点、视觉压缩，以及让多台机器人观测在同一节拍到达GPU的编排系统。只有可控场地、宽松时延预算和足够复杂的任务同时成立，改造才有经济意义。

## 供给链与商业含义

端侧Jetson和数据中心GPU争夺相同的先进节点，但近期机器人量太小：报告估算2030年100万颗、约400mm²的Jetson级芯片只需要约1万片晶圆。真正约束不是总晶圆，而是每台机器人消耗多少先进硅和DRAM。报告估算，当一张GPU服务超过约7台机器人时，共享GPU的硅面积/机器人更低；DRAM交叉点约5台/卡。

这意味着Nvidia可能同时受益于两条路线：端侧卖Jetson，云端卖B300/Rubin与网络。但机器人厂商的差异化不会只来自硬件采购，而来自模型压缩、任务分层、网络工程、安全认证和调度数据。

## 风险、证伪与监测

- RoboTTT是计时重构，不验证真实准确率；并发12台是特定硬件、负载和deadline结果。
- 无线改造、云安全、视频上行和故障冗余可能显著抬高云端TCO。
- 端侧模型效率若进步更快，云端推理需求可能下降；反之，规划模型迅速扩大则强化云端。
- 观察实际机器人每日工作小时、每GPU并发、p99抖动、断网降级、安全认证和客户是否允许数据出域。

| 结论项 | 判断 |
|---|---|
| 核心论点 | 安全/动作端侧化，复杂低频规划池化，是最可能的混合均衡 |
| 最强证据 | 新版12机器人/B300测试、利用率敏感TCO、五类部署案例 |
| 估值含义 | Nvidia双端受益；网络、调度和合规是被低估的价值层 |
| 催化剂 | 规模部署、机器人专用网络、云端System 2商用 |
| 主要风险 | 基准不可泛化、网络尾延迟、客户数据限制、端侧算法跃迁 |
| 行动条件 | 看到真实站点的p99成功率、利用率和全栈TCO后再上调云端算力需求 |
| 信心 | 中等 |
