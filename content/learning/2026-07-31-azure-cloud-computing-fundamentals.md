## 为什么要学云计算基础？

作为科技股投资者，理解云计算是读懂微软、亚马逊、谷歌财报的必要前提。Azure、AWS、Google Cloud每季度财报都充斥着IaaS、PaaS、SaaS、SLA等术语。这门课是市面上最清晰的中文入门资料之一，用人话把这些概念说清楚了。

## 一、云的分类：公有云、私有云、混合云、社区云

### 公有云（Public Cloud）

由第三方云服务商（微软、亚马逊、谷歌）拥有并运营的云基础设施，通过互联网向任何付费用户提供服务。

**特点**：
- **按需付费**：用多少付多少，不用购买硬件
- **无限扩展**：理论上无上限，企业不需要自己预测容量
- **零维护**：服务器、网络、冷却系统全由云商管理
- **多租户**：多个用户共享同一物理硬件（通过虚拟化隔离）

**代表**：AWS、Azure、Google Cloud、阿里云、腾讯云

**适用场景**：初创公司、中小企业、需要快速扩容的业务

### 私有云（Private Cloud）

企业自行建设和运营的专用云基础设施，只为内部使用。

**特点**：
- **完全控制**：数据不离开企业边界
- **定制化**：可根据业务需求深度定制
- **高安全性**：符合严格合规要求（金融、医疗、政府）
- **高成本**：需要自购硬件、自建运维团队

**代表产品**：VMware vSphere、微软Azure Stack、OpenStack

**适用场景**：银行、医院、政府机构等对数据主权要求极高的行业

### 混合云（Hybrid Cloud）

公有云和私有云的结合，通过VPN或专线互联，数据和应用可以在两端灵活流转。

**最典型的使用场景**：
- 日常业务跑在私有云（安全合规）
- 高峰期（双十一、春节）自动扩展到公有云（弹性扩容）
- 开发测试环境用公有云（便宜），生产环境用私有云（安全）

这是目前大型企业最主流的部署模式，也是微软Azure混合云战略的核心卖点。

### 社区云（Community Cloud）

多个有相似需求的组织共享的云基础设施（比如同一行业的多家医院共建医疗云）。现实中相对少见，主要在政务、医疗、金融行业有案例。

## 二、什么是云计算？核心定义

云计算的本质是：**把计算资源（服务器、存储、网络、软件）像水电一样，通过互联网按需提供给用户使用**。

美国国家标准与技术研究院（NIST）定义的云计算五个核心特征：
1. **按需自助服务**：用户可以不经人工干预，自行获取资源
2. **广泛网络访问**：通过标准网络协议，从任何设备访问
3. **资源池化**：多租户共享物理资源，通过虚拟化隔离
4. **快速弹性**：资源可快速扩展或缩减
5. **可计量服务**：资源使用情况被监控和计费

## 三、IaaS / PaaS / SaaS 的核心区别

这是理解云计算商业模式最重要的分层概念。可以用"盖房子"类比来理解：

### 类比：自己盖房 vs 租房 vs 住酒店

| 模式 | 你管什么 | 云商管什么 | 类比 |
|------|---------|-----------|-----|
| **自建机房** | 一切（硬件到应用） | 什么都不管 | 自己买地盖房 |
| **IaaS** | 操作系统、应用、数据 | 硬件、网络、存储 | 租毛坯房，自己装修 |
| **PaaS** | 应用代码、数据 | 硬件+操作系统+运行环境 | 租精装房，自己摆家具 |
| **SaaS** | 数据和使用方式 | 一切 | 住酒店，拎包入住 |

### IaaS（基础设施即服务）

用户租用虚拟机、存储、网络等底层基础设施，自己安装操作系统、配置环境、部署应用。

**典型产品**：
- Azure Virtual Machines（虚拟机）
- AWS EC2
- Google Compute Engine

**适用对象**：有IT团队的企业，需要完整控制权；或开发者测试复杂应用

**优势**：灵活性最高，可以运行任何软件
**劣势**：维护工作量最大，需要自己打补丁、做备份

### PaaS（平台即服务）

云商提供完整的开发和运行环境，开发者只需要写代码和管理数据，不用关心底层基础设施。

**典型产品**：
- Azure App Service（部署Web应用）
- AWS Elastic Beanstalk
- Google App Engine
- Azure SQL Database（托管数据库）

**适用对象**：开发团队，想专注业务逻辑而非基础设施
**优势**：大幅降低运维负担，加速开发迭代
**劣势**：定制化空间受限，存在厂商锁定风险

### SaaS（软件即服务）

完整的软件应用通过互联网交付，用户无需安装、维护任何东西，直接通过浏览器或App使用。

**典型产品**：
- Microsoft 365（Word/Excel/Teams的云版本）
- Google Workspace（Gmail/Docs/Sheets）
- Salesforce（CRM）
- Zoom、Slack、Dropbox

**适用对象**：所有人，无技术门槛
**优势**：零运维，永远用最新版本，随时随地访问
**劣势**：数据控制权在云商，定制化能力最低

### 投资视角：三层模式的利润结构

| 层次 | 毛利率 | 护城河 | 代表 |
|------|-------|-------|-----|
| IaaS | 20-40% | 规模经济 | AWS、Azure计算 |
| PaaS | 50-70% | 生态锁定 | Azure SQL、Databricks |
| SaaS | 70-90% | 用户习惯+数据网络效应 | M365、Salesforce |

这解释了为什么微软花大力气把用户从Office永久授权（买断）迁移到M365订阅（SaaS）：SaaS的利润率和ARR可见度远高于传统软件。

## 四、我为什么要上云？——上云的核心价值

课程中用通俗语言讲解了上云的四大商业价值：

### 1. 资本支出转运营支出（CapEx → OpEx）

**传统模式**：买服务器需要一次性大额资本支出，3-5年折旧，采购周期6-12个月，且不可避免地过度采购（买大了浪费，买小了不够用）。

**上云之后**：按月按量付费，属于运营支出，财务灵活性大幅提升。初创公司最爱——零初始投入，验证商业模式后再扩容。

### 2. 弹性扩展（Elasticity）

这是云计算最核心的价值之一。

**场景**：一个电商网站，平时流量1000 QPS，双十一高峰期达到100,000 QPS。

**传统方案**：必须按峰值采购服务器，峰值过后98%的时间资源空闲浪费。

**云方案**：日常用1台服务器，高峰前10分钟自动扩展到100台，高峰结束后自动缩容回1台。只为实际使用的时间付费。

### 3. 全球化部署

Azure在全球60+个地区（Region）有数据中心，企业可以一键在任何地区部署应用，让全球用户都获得低延迟体验。对于出海企业，这是极大的优势。

### 4. 高可用性和灾备

云商的数据中心具备多路电源、多路网络、自动备份、跨区域容灾。企业自建机房达到同等级别的可靠性，成本远高于上云费用。

## 五、Azure核心服务概览

Azure提供超过200种云服务，课程中介绍了几个最核心的类别：

### 计算（Compute）
- **Azure Virtual Machines**：Windows/Linux虚拟机，IaaS核心
- **Azure Kubernetes Service (AKS)**：容器编排，适合微服务架构
- **Azure Functions**：无服务器计算（Serverless），按函数调用次数付费
- **Azure App Service**：Web应用托管平台，PaaS

### 存储（Storage）
- **Azure Blob Storage**：非结构化数据（图片、视频、文件），对标AWS S3
- **Azure Disk Storage**：虚拟机磁盘
- **Azure Files**：托管文件共享服务

### 数据库（Database）
- **Azure SQL Database**：托管关系型数据库
- **Azure Cosmos DB**：全球分布式NoSQL数据库
- **Azure Database for PostgreSQL/MySQL**：开源数据库托管服务

### 网络（Networking）
- **Azure Virtual Network (VNet)**：隔离的私有网络空间
- **Azure Load Balancer**：流量分发
- **Azure CDN**：内容分发网络，全球加速

### AI与机器学习
- **Azure OpenAI Service**：GPT-4/o1/o3等模型的企业级API接口
- **Azure Machine Learning**：模型训练和部署平台
- **Azure Cognitive Services**：视觉、语音、语言等预训练AI API

## 六、云服务可靠性——SLA怎么看？

SLA（Service Level Agreement，服务等级协议）是云商对可用性的法律承诺。

### 常见SLA级别解读

| SLA | 年停机时间 | 月停机时间 |
|----|---------|---------|
| 99% | 87.6小时 | 7.2小时 |
| 99.9%（三个九） | 8.76小时 | 43.8分钟 |
| 99.95% | 4.38小时 | 21.9分钟 |
| 99.99%（四个九） | 52.6分钟 | 4.4分钟 |
| 99.999%（五个九） | 5.26分钟 | 26.3秒 |

Azure大多数核心服务承诺**99.9%~99.99%**的SLA。

**重要提示**：单服务SLA ≠ 整体应用SLA。如果你的应用依赖5个服务，每个99.9%，总可用性约为99.5%（相乘）。这就是为什么架构师需要做冗余设计（多可用区部署）。

### 违反SLA的赔偿

不是退款，而是服务积分（Service Credit）。通常：
- 停机时间超过SLA → 赔10%-25%的月费积分
- 积分只能用于购买Azure服务，不能提现

## 七、如何选择云服务商？

课程最后给出了选择云厂商的实用框架：

### 选择维度

1. **已有技术栈**：如果团队用.NET/Windows，Azure天然兼容；Python/开源技术栈，三家都行
2. **已有企业合同**：使用M365的企业往往能通过EA协议获得Azure优惠；AWS有大量创业公司信用额度
3. **地理覆盖**：需要在特定地区（中国大陆、中东、政府专区）部署，先检查各家的Region覆盖
4. **特定AI/ML服务**：Azure OpenAI独家GPT访问；Google Cloud的Gemini和TPU；AWS的Bedrock多模型
5. **定价比较**：同类服务三家价格相近，但具体服务有差异，建议用定价计算器对比

### 三大云厂商定位

| 维度 | AWS | Azure | Google Cloud |
|------|-----|-------|-------------|
| 市场份额 | ~30% | ~25% | ~12% |
| 优势 | 服务最全面、开发者生态 | 企业客户、微软生态 | AI/ML、数据分析 |
| 劣势 | 学习曲线陡 | 企业外用户体验 | 市场份额较小 |
| AI产品 | Bedrock、Nova | Azure OpenAI | Vertex AI、Gemini |

## 八、投资者视角总结

理解云计算基础对科技股投资的直接价值：

1. **读懂财报**：Azure的"Intelligent Cloud"营收、AWS的"AWS Revenue"、GCP的单独披露——都是这些基础服务的汇总
2. **判断护城河**：SaaS（M365、Google Workspace）的高毛利+高续约率 → 最强护城河；IaaS竞争最激烈，价格战压力最大
3. **AI加速器**：Azure OpenAI、AWS Bedrock、Vertex AI是当前AI需求增长最直接的受益方，也是为什么分析师给这三家如此高的估值溢价
4. **迁移成本**：PaaS和SaaS的厂商锁定（Vendor Lock-in）是护城河，也是为什么企业客户粘性极高、NRR（净留存率）能超过130%
